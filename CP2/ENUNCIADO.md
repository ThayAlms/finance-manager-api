# Enunciado do Checkpoint 2

**Data prevista:** 06/10

## Objetivo

O segundo Checkpoint deverá apresentar uma evolução significativa do CP1.

Nesta etapa, o backend deverá estar mais consolidado e integrado a uma aplicação com interface visual. O grupo deverá também revisar o banco de dados, melhorar a documentação, implementar testes iniciais e incorporar recursos relacionados a LLMs.

## 1. Evolução do backend

As funcionalidades desenvolvidas no CP1 deverão continuar funcionando.

Problemas identificados anteriormente deverão ser corrigidos.

O backend deverá apresentar maior maturidade em relação a:

- validações;
- tratamento de erros;
- organização;
- segurança;
- estrutura das respostas;
- regras de negócio.

## 2. Frontend da aplicação

O grupo deverá desenvolver uma interface para utilização do sistema.

O frontend deverá:

- consumir a API desenvolvida pelo grupo;
- permitir interação com as funcionalidades principais;
- possuir navegação coerente;
- apresentar dados obtidos do backend;
- permitir cadastro ou alteração de informações quando aplicável;
- possuir tratamento visual de erros;
- apresentar feedback das operações realizadas.

Não será considerada suficiente uma interface composta somente por páginas estáticas.

## 3. Dashboard de controle

A aplicação deverá possuir um dashboard relacionado ao contexto do projeto.

Poderão ser utilizados:

- indicadores;
- métricas;
- gráficos;
- tabelas;
- históricos;
- alertas;
- dados consolidados.

O dashboard deverá utilizar dados reais provenientes do backend ou do banco da aplicação.

## 4. Otimização da API

O grupo deverá analisar sua API e realizar melhorias.

Poderão ser consideradas:

- redução de requisições desnecessárias;
- paginação;
- filtros;
- consultas otimizadas;
- melhor tratamento de erros;
- validações;
- organização das respostas;
- melhorias de desempenho.

As otimizações realizadas deverão ser explicadas durante a apresentação.

## 5. Normalização e revisão do banco

A estrutura do banco deverá ser revisada considerando:

- duplicidade de informações;
- geração de relatórios;
- classificação de informações;
- assistente inteligente;
- resumo de informações;
- análise textual;
- recomendações;
- geração de conteúdo;
- interpretação de dados;
- agentes;
- apoio à tomada de decisão.

A utilização da LLM deverá possuir relação real com o problema do projeto.

Não será considerada suficiente a inclusão de um chatbot genérico sem integração com as regras de negócio.

O grupo deverá explicar:

- modelo ou serviço utilizado;
- finalidade da LLM;
- dados enviados;
- resposta obtida;
- como a resposta é utilizada pela aplicação;
- limitações identificadas;
- cuidados com segurança e dados sensíveis.

## 9. Apresentação do CP2

A apresentação deverá demonstrar:

- evolução em relação ao CP1;
- aplicação frontend;
- comunicação frontend/backend;
- dashboard;
- banco revisado;
- otimizações;
- testes;
- integração com LLM;
- atualização do Trello ou Notion.

## Entregáveis do CP2

- Repositório GitHub atualizado.
- README atualizado.
- Backend atualizado.
- Frontend funcional.
- Dashboard.
- Banco de dados revisado.
- Swagger atualizado.
- Testes iniciais.
- Integração com LLM.
- Trello ou Notion atualizado.
- Apresentação.
